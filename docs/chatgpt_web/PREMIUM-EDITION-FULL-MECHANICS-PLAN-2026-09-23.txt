A September 23 project decision makes a Zodiac relationship / dating-sim system a new pillar: the player builds relationships with recurring Zodiac bosses through conversations, persuasion and gifts drawn from the game itself.
The official game website was observed on 2026-09-23 to promise a later full version with more NPCs, items and mechanics, including daily Zodiac modifiers and a Zodiac boss. AI opponents, multiplayer and 3D presentation have been removed from the active plan; they are not missing requirements for this edition.

TARGET FEATURE SET
1. Daily Zodiac modifiers — required full-mechanics feature.
Design the complete calendar and all twelve Zodiac identities. Specify when a modifier is selected and shown, what it changes, its duration, interactions with card rules / Drinks / relics / services / scoring, how it can be countered, and how it is represented in seed/save/replay. Effects remain design-required until specified.
2. Zodiac bosses — required full-mechanics feature.
Specify each boss's identity, arrival and encounter timing, rules, telegraph, player response, success/failure outcomes, campaign accounting and persistence. Define how a boss interacts with the daily modifier without hidden or contradictory rules.
3. Zodiac relationships / dating-sim system — required new full-mechanics pillar.
Design recurring boss characters and a relationship arc that develops through play. Use context-aware persuasion conversations as an influence: characters may ask, challenge, demand, bargain, or react to prior run choices. Gifts should use meaningful game resources such as cards, Drinks, relics or money where appropriate, so relationship decisions compete with the run's economy and build. Giving a requested item must not guarantee affection; personality and context should matter. These are design directions, not final rules: define encounter cadence, conversation choices, relationship state, persistence, gift eligibility/value, refusal outcomes, rewards and boss-mechanic interactions before implementation. Do not assume bosses are recruited or that relationships are simple score multipliers.
4. Expanded NPC and item content — required by the public full-version promise.
Define the complete roster and inventory against the six current roles. Each new service needs eligibility, phase/day timing, price/payment authority, repeat behavior, save/resume behavior, bilingual copy and Handbook entry. Each item needs ownership, offer, equip/slot rules, gameplay effect, timing and accounting.
5. Special weekday mechanics and story chains — outstanding full-game mechanics from the project README.
Define the calendar schedule, authored narrative beats, player choices, state carried across days, effects on NPCs, rewards and failure/skip behavior. The stories and effects remain to be written.

DESIGN AND IMPLEMENTATION ORDER
A. Freeze v1.0.3 as the public reference and audit post-tag working-tree changes before reusing them.
B. Write source-of-truth rule specs and a content matrix for all Zodiac modifiers, bosses, relationships/conversations/gifts, NPCs, items, weekday mechanics and story chains.
C. Define compatibility contracts: relationship state scope/persistence, seed versioning, save migration, campaign ordering, payment/scoring authority, bilingual Handbook/help and accessibility/readability.
D. Implement and accept deterministic single-player additions first. Every effect needs a player-visible explanation, exact timing and rule-level regression coverage.
E. Prototype the boss conversation loop against real campaign state and the existing wallet, Drinks, relics and card ownership authorities; first settle timing, choices and persistence. Then integrate relationship state with bosses, daily modifiers and story progression.
F. Run integrated campaign, save/resume, seed reproduction, balance, rendered-UI and human-play acceptance before packaging. A passing local rules suite alone does not establish full release acceptance.
