# Trigger-first scoring presentation

Implemented: scoring remains authoritative in ScoringPipeline and VndWallet. Each scoring pass now carries value snapshots in presentation_hits; MatchUI converts those point receipts at the current payout multiplier and VND rate. Presentation never applies a wallet transaction.

- Physical card hits include ID, face, printed properties and points after the local multiplier.
- Making/Extend echoes immediately follow the same card. Whole Set/Run replays identify their source card and remain finite. New Melds at SET sizes 4/8/12/... and perfected A–K RUNs retain one native full-meld retrigger.
- Every Extension pays its intrinsic delta first. If the resulting SET reaches 4/8/12/... or the RUN becomes a perfected A–K sequence at 13 cards, one complete-meld retrigger follows that delta; Gieo full-meld retriggers follow it as additional finite passes.
- Ordinary extensions show committed-card hits followed by an explicit meld-delta adjustment. Other modifier/clamping differences are explicit signed adjustments. Hit totals exactly reconcile to each existing pass total.
- Exhaustion uses the same receipt and then overlapping card returns. It does not reapply Making echoes or duplicate payout.
- The compact receipt and its labels ignore pointer input. Existing ordinary gameplay remains unlocked.
- By default, the first three card triggers each hold for 0.36 seconds. Subsequent hits gradually accelerate by 9% per card trigger to a 0.045-second minimum. Only cards already triggered determine speed; total event count, elapsed time and queue backlog never fast-forward the resolution. The counter persists across meld replays and resets for each new resolution. Replay announcements gradually reach a 0.14-second floor. Every hit receives its own frame-visible beat.
- Clicking, pressing a non-repeating key/controller button, or tapping during money feedback fast-forwards the current queue. Scoring uses the existing 0.012-second beat and skips remaining card-scroll reveals; money tweens, transfers, phase feedback, major-event bursts and exhaustion returns run eight times faster. A request during an active beat/tween takes effect immediately. This press is consumed so it cannot also activate a card or focused gameplay button. Later inputs keep their normal meaning. Menu/modal navigation and incidental motion, wheel scrolling, releases and key echoes do not request acceleration. The next queue and cancelled queues reset to normal speed.
- Concurrent scoring/ordinary-transfer bills remain capped at eight; audio is throttled. Default shared bill flight duration is 0.48 seconds. Fast-forward affects presentation only and never changes gameplay speed, rules or wallet transactions.
- Tutorial receipt cancellation restores the shared layout and invalidates stale queue completions.

Validation: tests/test_money_presentation.gd covers order, physical identity, finite replay sources, extension delta, exhaustion, signed adjustments and manual pacing policy. tests/trigger_presentation_smoke.gd covers runtime wallet separation, input-transparent labels, cancellation, layout restoration and ghost cleanup. tests/money_fast_forward_smoke.gd checks normal pacing beyond four seconds, native mouse/keyboard/controller/touch requests, every frame-visible receipt, current/next queue behavior, transfers, phase/burst feedback, button-input consumption, complete encoded gameplay invariance and cancellation. The Windows validation gate includes this regression; existing runtime and tutorial smokes also exercise integration.

Visual QA uses synthetic live melds, not a saved campaign. The September 29 automatic four-second compression is replaced by the user-requested manual fast-forward. Extremely long chains retain the gradual ramp until the player requests acceleration; no receipt or payout is dropped.

Each physical card rocks left/right on its own scoring hit and immediate retrigger. Other cards, score text, and the table remain still. A receipt card shakes only as a fallback when its physical table card is no longer available. Shakes restore the original rotation and pivot on completion, retrigger, and cancellation.
